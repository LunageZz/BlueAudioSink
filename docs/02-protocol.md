# 传输协议 v1（两端唯一契约）

> 本文件是 PC 端与 Android 端的**唯一事实来源**。任何一端实现前必须先读本文件；
> 实现与本文不符时，以本文为准（或先修订本文并同步另一端）。

## 1. 网络与端口

| 用途 | 协议 | 端口 | 方向 |
| --- | --- | --- | --- |
| 发现 / 控制 | UDP | **45678** | 双向 |
| 音频 | UDP | **45679** | 手机 → PC |

所有多字节整数均为**小端（little-endian）**。

## 2. 统一包头（16 字节）

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 4 | magic | bytes | ASCII \`"BAS1"\`（0x42 0x41 0x53 0x31） |
| 4 | 1 | type | u8 | 见下表 |
| 5 | 1 | flags | u8 | bit0 = 断流标记（DISCONTINUITY） |
| 6 | 2 | reserved | u16 | 必须为 0 |
| 8 | 4 | seq | u32 | AUDIO 包递增序号，从 0 开始 |
| 12 | 4 | timestampUs | u32 | 采集时刻（微秒，低 32 位） |
| 16 | N | payload | bytes | 依 type 而定 |

**type 定义**

| 值 | 名称 | 方向 | payload |
| --- | --- | --- | --- |
| 1 | AUDIO | 手机→PC | PCM 数据 |
| 2 | START | 手机→PC | 空 |
| 3 | STOP | 手机→PC | 空 |
| 4 | PING | 手机→PC | 空 |
| 5 | PONG | PC→手机 | 4 字节：PC 接收时刻（微秒，u32） |
| 6 | OFFER | PC→手机广播 | UTF-8 设备名 + \`0x00\` + 4 字节音频端口（u32） |
| 7 | HELLO | 手机→PC | UTF-8 设备名 |

## 3. 音频格式

| 项 | 值 |
| --- | --- |
| 编码 | PCM 有符号 16-bit 小端 |
| 采样率 | **48000 Hz** |
| 声道 | **2（立体声，交错 L/R）** |
| 每包时长 | **10 ms** = 480 帧 = **1920 字节** payload |
| 包总长 | 16 + 1920 = **1936 字节** |
| 包速率 | 100 包/秒 |
| 带宽 | 约 **1.55 Mbps** |

## 4. 时序

\`\`\`
手机                                        PC
 |---- HELLO（可选） --------------------->|
 |---- START ----------------------------->|  进入接收态，初始化缓冲
 |---- AUDIO(seq=0,ts) ------------------->|
 |---- AUDIO(seq=1,ts) ------------------->|  入抖动缓冲，按序播放
 |         ...                             |
 |<--------------------- PING -------------|  每 2 秒
 |---- PONG(ts=PC接收时刻) ---------------->|
 |---- STOP ------------------------------>|  排空剩余后回到待机
\`\`\`

- PC 收到 START 后清空缓冲、重置 seq 基线。
- PC 收到 STOP 后继续播放缓冲内剩余数据，播放完转待机。
- 超过 **5 秒**未收到任何 AUDIO 包 → PC 自动转待机并释放。

## 5. 延迟与时钟

- \`timestampUs\` 为手机采集该包首帧的时刻（相对手机开机时间的微秒数低 32 位）。
- 双方时钟不同源，PC 端用 PING/PONG 估算单程时延与时钟偏移：
  - \`RTT = T_pong_recv − T_ping_send\`
  - \`offset ≈ T_ping_send − T_pong_payload − RTT/2\`
- 界面显示：RTT、缓冲深度、估算延迟（offset + 缓冲 + 播放缓冲）、丢包率。
- **估算延迟仅用于展示**，不参与播放调度。

## 6. 抖动缓冲（PC 端）

- 载体：\`BufferedWaveProvider\`（容量 1 秒）+ \`WasapiOut\`（共享模式，50 ms）。
- 目标缓冲自适应：

\`\`\`
每 500 ms 评估一次：
  jitter  = 最近 2 秒内 (到达间隔 − 发送间隔) 的平均绝对偏差
  target  = clamp(40ms + 4 × jitter, 40ms, 200ms)
  buffer += clamp(target − buffer, −5ms, +10ms)   // 增加快、减少慢
\`\`\`

- 缓冲不足 → 补静音；超出上限 → 丢弃最旧数据。

## 7. 丢包与异常

| 情况 | 处理 |
| --- | --- |
| 单个包缺失 | 静音填充（避免爆音） |
| 连续缺失 > 5 包 | 置 flags.bit0=1，插入 10 ms 淡出，记录断流事件 |
| seq 跳变 > 10 | 视为重置：清空缓冲，重建 seq 基线 |
| 5 秒无包 | 转待机，释放播放器 |
| magic 不符 | 丢弃该包并计数 |

## 8. 发现

- PC 每 **2 秒**向 \`255.255.255.255:45678\` 广播 OFFER。
- OFFER payload：\`设备名UTF8\` + \`0x00\` + \`音频端口(u32)\`。
- 手机监听 45678，收到 OFFER 后展示设备；用户选择后向该 IP 的 45679 发送音频。
- 广播失败时可手动输入 IP（MVP 必须支持）。

## 9. 兼容与演进

- 预留 \`reserved\` 与 \`flags\` 其余位。
- 后续若引入 Opus：新增 type=8（AUDIO_OPUS），通过 START payload 协商编码；PCM 保持默认。
