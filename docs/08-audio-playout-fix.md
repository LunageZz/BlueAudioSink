# 音频播放机制修复与验证

## 实施规格（2026-10-30，先于实现）

1. 删除按系统时钟每 5 ms 转移一包的第二播放节拍。接收后经有界重排，把连续 PCM 尽快送入唯一播放缓冲；WASAPI 的 Read 决定实际消费速度。
2. 每 500 ms 仅更新预缓冲/真实欠载恢复阈值，最低为配置的 BufferBaseMs（默认 80 ms）。健康播放不再为追目标插静音或删除音乐。
3. 在 IWaveProvider.Read 层统计实际补零帧与欠载事件；真正缺数后保持未消费音频，攒够阈值再恢复。正常停止排空与欠载分开统计。
4. UDP 为小幅乱序提供 20 ms 等待窗口；只有截止时仍缺包才补 5 ms 静音并计丢包。迟到的旧包不能重置会话。
5. Android 短读攒满再出包，采样与发送使用一致时基；parkNanos 后重新检查截止时间；发送失败仍消耗序号。记录环空、溢出、短读、发送失败以防“零网络丢包”掩盖源端缺口。
6. 增加离线回归：连续 PCM 保真、实际补零统计、完整预缓冲恢复、UDP 乱序恢复与真正缺包截止。运行真实 Android→Wi-Fi→PC 音乐传输，结合播放补零统计和输出录音核验。

本阶段优先消除确定的主动插零/删样和错误调度；不引入音色补偿。独立设备采样时钟长期漂移仍需长时间实测，短期通过充足缓冲与显式溢出日志监测，不以静默删样掩盖。

## 验证记录

### 构建与回归

- Windows Release 自包含裁剪发布成功；只有既有 NAudio/COM 裁剪警告，无 C# 编译错误。
- Android `:app:assembleDebug --offline` 成功，新 APK 已覆盖安装到 Redmi K70 Ultra。
- `tools/AudioRegression` 的 **10 项回归全部通过**，含 90 秒模拟连续流逐字节相同、重排、真实补零、恢复、正常排空和重复 START 隔离旧消费者。
- 修复后的真实发送/播放路径已在手机及 H180 Plus (Type C) 输出设备运行。默认 80 ms 预填，稳定期不主动插零或删样。

### 真实音频传输（按实际轮次完整保留）

测试文件为 `D:/本地资源库/Voice materials/who do you want.mp3`，手机文件 `/sdcard/Music/test.mp3`，MD5 均为 `f90c9d2e80237b34274754c7717a4c79`。网易云播放器，Android App + Wi-Fi UDP + PC WASAPI。Windows 回环录音保存为**有正确文件头的标准 WAV**：48000 Hz / float32 / stereo。

第二轮 10 ms 异常发生在录音 17.4863 s；原曲对应位置约 22.1901 s 非静音，前后匹配时移不变，相关系数约 0.9999997。该轮没有输入零帧诊断，无法唯一归因；其后的延长观察还出现 2 次真实输出欠载、共 10320 帧补零，说明只修队列机制仍不能宣称绝对稳定。这些异常没有从报告中删去。

第三轮加入输入零帧与 Read 间隔诊断。最长零帧为 81985 帧 = 1708.02 ms，**在进入播放缓冲前已存在**，与输出录音最长静音一致。录音前几秒无法与原曲匹配，14 s 后可与原曲开头对应，确认包含曲目切换；该轮静音不能直接算成 PC 缓冲故障。MMCSS 已成功注册，Read 最大调用间隔 11.58 ms。

随后不进行曲目切换/控制操作，录制稳定播放段，29.96 s 内没有 ≥0.5 ms 的内部零段，没有应用补零、欠载或溢出。MMCSS 版本从 03:43:41.992 到 03:46:02.218 共 29 个统计样本均报告上述三项为 0，missing 窗口最大为 0。会话起步 late=2，之后未增加，不能将它隐藏成“全程没有任何丢弃”。

验证结论：已确认的主动插零/删样、二次播放节拍和错误欠载判定已移除；最终稳定段未复现原来的周期性 5–10 ms 断点。**不宣称所有主观噪点或所有网络条件已解决**，第二轮孤立 10 ms 异常未唯一定位，长期设备采样时钟漂移也仍需更长测试。此次不能证明所谓“手机音效造成严重动态压缩”。

## 真机复核中的追加定位

第二轮输出录音中出现 1 段 10 ms 静音，但 provider 补零和网络缺包均为 0。与原 MP3 对齐后，缺口前后各 1 秒的归一化相关系数约 0.9999997，原曲对应位置非静音。追加以下诊断/修复：记录进入播放缓冲的最长零帧段，区分手机已输出静音与下游渲染问题；记录 WASAPI Read 调用最大间隔；将真正的 WASAPI 消费线程注册为 MMCSS Audio/High，避免普通优先级线程的渲染截止时间被其他任务挤占。注册在该线程首次 Read 时执行，停止回调在同线程注销；失败只记录、不阻止播放。
