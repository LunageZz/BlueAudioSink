# 电脑端界面与交互优化（2026-10-30）

## 目标与边界

保留 Win32/GDI、蓝牙/Wi-Fi 互斥机制和现有音频协议。此次主要修改界面组织、状态呈现和设置入口，不调整传输/补偿算法。

## 实施规格（先于实现）

- 顶部固定导航：品牌、蓝牙、Wi-Fi、设置。设置在 Wi-Fi 右侧，两模式及设置页均可访问；返回设置前的模式，不停止音频。
- 将状态从导航行中独立成主卡片，使用大标题、简短说明和手机/接收/输出三个阶段。不能把收到静音 PCM 等同于正在播放有声内容。
- 对 Wi-Fi 增加只读观测：最近音频包年龄、最近非静音信号、输出播放器是否实际工作、排空/恢复阶段、当前输出设备名。它们不参与音频调度；UI 据此区分等待连接、待发送、准备播放、播放中、当前静音、暂时中断、恢复中、故障。
- Wi-Fi 页按状态、设备流向、三项核心指标（网络往返、缓冲、近 10 秒丢包）组织。端口、累计收包/缺包/恢复次数放入“连接详情”展开区。删除成串的互斥机制和缓冲解释。
- 共享设置按通用与连接偏好分组：播放设备、开机启动、蓝牙自动连接、Wi-Fi 预缓冲档位（80/120/160 ms）、日志入口。蓝牙专属选项明确标识；缓冲档位只改现有首次/恢复阈值，不改正在播放的 PCM。
- 在设置中主动更换播放设备时，蓝牙沿用既有路由设置，Wi-Fi 请求后台重建输出播放器；模式不变。页面显示实际输出名，不能用列表第一项冒充当前输出。
- 保留按需重绘与双缓冲。补齐键盘 Tab/Enter/Space/Escape、焦点描边、按钮按压/悬停反馈和无效控件的禁用态。
- 默认窗口约 700×680 DIP（最小外框 600×640 DIP），设置最小尺寸以避免裁切；宽屏内容居中并限制最大宽度，文字按 DPI 缩放，状态与导航不抢同一行。

## 验证

构建、原音频回归、状态映射回归；桌面实测 Wi-Fi/蓝牙切换、从两模式进入同一设置页、返回、详情展开/折叠、键盘操作、下拉、最小窗口和较大窗口。完成后同步本地 Release 并提交 Git。


## 完成与核验

- 全局设置入口位于 Wi-Fi 按钮右侧，蓝牙/Wi-Fi/设置页共用导航；进入/返回设置不切换模式。
- 首页按主状态、发送/输出设备、三项指标分层，默认收起端口与计数。撤下不够严谨的单程“估算延迟”，显示有明确测量语义的网络往返时间；静音根据收到的 PCM 判断，不受电脑其他应用出声影响。
- 修正电脑地址选择：有手机端点时按该端点的本机路由取地址；待连接时优先活动 Wi-Fi 地址，避免显示无关 VPN 地址。增加复制地址与故障重试。
- 设置按播放/启动和模式连接偏好组织，蓝牙专属选项明确标识。80/120/160 ms 使用已有预填/恢复阈值，测试选择 120 后已恢复原 80 ms；更换输出时只重建输出播放器，不改变传输协议。
- 增加原生最小尺寸、最大化、宽屏最大内容宽度 820 DIP、键盘焦点和禁用状态。修正返回后焦点框残留、下拉字体随 hover 改变、悬停边框传参无效的问题。
- 发布构建成功，C# 编译 0 错误；裁剪发布仅有既有 NAudio/COM 警告。原有 10 项音频回归和新增 5 项状态映射测试共 15 项通过。
- 桌面实测：两种模式进入同一设置页、返回保留当前模式、详情开关、输出就地下拉与 Escape、预缓冲选择与保存反馈、Tab/Enter 返回焦点、窄窗口及最大化/还原均完成。窄窗口宽度约为最小外框 600 DIP，核心卡片和设置未越界。
- 进入设置、操作显示层不主动停止发送/接收；本轮没有重新录制真机音质样本。音频算法沿用已修复版本，连接状态通过只读观测细化；不把 UI 单元测试写成真机传输验收。
- 当前保留 Win32/GDI 与原依赖，无新增 UI 框架或图片资源。自绘控件支持键盘操作，本轮未新增完整 UI Automation 节点。

本地 Release 同步到 `artifacts/BlueAudioSink-0.1.0.exe`、`artifacts/pc/BlueAudioSink.exe` 及默认 publish 目录；Android 产物本轮不变。

## 选中态修正

顶部高亮表示当前可见页面：设置页打开时，仅设置使用蓝底白字；蓝牙和 Wi-Fi 保持普通按钮样式。返回时恢复当前音频模式页面的高亮。只修改导航绘制，不改变音频模式或连接生命周期。

## 紧凑布局修订

默认窗口由 700×680 DIP 收紧为 520×500 DIP，最小外框 480×500 DIP；面积约减少 45%。缩减边距、卡片高度和导航按钮宽度，取消状态大卡片外框，三项指标合并为一条紧凑指标区。正文仍保持 14 DIP，状态标题 20 DIP、指标值 24 DIP，说明文字不低于 12 DIP。设置页同步紧凑，绘制、命中区域和键盘焦点使用一致坐标；不改音频机制。

本次核验：Release 发布构建通过；实际启动检查 520×500 默认窗口下的蓝牙、Wi-Fi、连接详情及统一设置页，文字和操作区域无重叠，详情展开正常，三项导航保持当前页面独占选中态。本地两个发布入口与默认 publish 程序同步更新。

## 统一设备设置（实施前规格）
播放设备只允许在设置中调整，蓝牙主页撤下手机列表和输出下拉，改为只读设备流向及连接/断开操作。设置新增“常规 / 连接设备”子页，保持 520×500 默认窗口；连接设备页列出已配对蓝牙手机，分页访问全部设备，点击后切换并保存首选手机。刷新仅在设备页提供。连接状态、正在连接、首选设备分开显示；Wi-Fi 模式下主动选择蓝牙设备即切换到蓝牙模式。切换前完整释放旧连接，避免覆盖连接引用遗留通道；音频补偿算法不改动。
Wi-Fi 与蓝牙共用“连接设备”页，按当前模式展示候选。Wi-Fi 候选从现有 HELLO / START / AUDIO 得到，不新增协议；列表保留当前 Wi-Fi 会话期间发现的手机并区分近期活动与未确认在线。选择后清空旧音频队列和播放器，锁定来源；其他手机的 START / AUDIO / STOP / HELLO 不得抢占或污染当前状态。候选选择不代替 Android 端的录音授权和开始发送，界面明确提示。模式关闭后清空 Wi-Fi 候选与来源锁定，避免把临时 IP 当永久设备身份。

本轮完成与核验：播放设备编辑控件只保留于「设置 → 常规」；蓝牙主页仅显示状态、发送/输出设备及连接/断开按钮。「设置 → 连接设备」在同一入口内切换蓝牙 / Wi-Fi 手机列表，每页 5 台，Wi-Fi 显示名称与端点以区分同名手机；刷新蓝牙列表、重新广播电脑发现信息均有反馈。保留窗口 520×500 DIP。蓝牙记住首选手机，连接新目标前释放旧连接。Wi-Fi 区分自动接收的当前设备与明确选择的来源，切换清空旧缓冲及旧统计，并过滤其他来源的控制/音频包。

核验：19 项回归全部通过，包含真实双 UDP socket 发送端的发现、切换、旧来源 START/AUDIO/STOP 隔离和新来源独立预缓冲；Release 发布成功（仅既有 NAudio/COM 裁剪警告）。桌面实际检查两类设置子页、蓝牙主页撤下重复控件、七个候选的两页访问和空闲状态说明；多候选使用本机 HELLO 测试数据，切换模式后已清理。现场一台 Android 正在发送 Wi-Fi 音频，重启和返回 Wi-Fi 后能继续接收。本轮没有两台实体 Android 的蓝牙/Wi-Fi 同场切换验收，也没有重新录制音质样本；双设备切换机制由 UDP 集成测试覆盖。Android APK 与音频补偿算法不变。

## Wi-Fi 防火墙设置（实施前规格）
设置新增紧凑的“网络”子页，保留 520×500 默认尺寸。用户可主动开启、修复或移除本程序的 Windows 防火墙入站规则，并只读重新检测状态。规则绑定当前 exe 路径，仅允许专用网络、LocalSubnet 来源、UDP 45678 与配置的音频端口（默认 45679），不关闭系统防火墙，不放行公共网络，不覆盖其他应用/用户规则。规则标识按程序路径固定，多次点击幂等；改端口或移动 exe 后重新配置。仅点击修改按钮时通过本程序独立 helper 请求 UAC，主界面继续运行，helper 在单实例/音频初始化之前执行并退出。取消授权、失败、规则不匹配、没有活动专用网络、策略限制分开反馈。检测成功/规则存在不等同于音频通路必然可用；第三方防火墙、明确阻断规则、网络隔离仍可能影响传输。开发验证不实际修改用户电脑防火墙。

本轮完成核验：增加「设置 → 网络」，保留小窗口及键盘导航，检测和提权操作在后台执行，期间按钮禁用。规则绑定当前 exe，按路径标识幂等更新，移除仅针对该路径的本程序规则；helper 在单实例锁之前处理，不启动第二个音频接收器。使用 Windows 自带 PowerShell 调用 Windows Firewall COM API，无新增 NuGet/UI 依赖，路径以 Base64 数据传递，固定脚本不拼接可执行的路径文本。开启/移除后回读校验程序、端口、专用配置、入站允许、局域网来源与边缘穿越关闭等属性。

Release 构建通过，仅既有 NAudio/COM 裁剪警告；原有 19 项音频/状态/双发送端回归通过；6 项防火墙专项检查通过，包括真实 Windows PowerShell 在隔离存储执行开启/重复开启/换端口/查询/重复移除，以及真实系统只读查询。桌面检查设置三子页与网络页：默认 520×500 中控件无重叠，查询异步返回，当前缺少活动专用网络的情况正确提示。没有点击真实开启/移除或操作 UAC，也未改变电脑防火墙；真实提权写入及取消授权流程未作端到端实测。Android 产物与音频算法不变。

## 修复 Shell 旧图标缓存（实施前规格）
已核对正在运行的 exe 路径及 PE 主图标资源（唯一图标组 32512，9 帧全为新图），旧绿点来自 Shell 仍缓存同路径旧图标。启动时声明稳定的 BlueAudioSink.Desktop AppUserModelID，并在当前安装位置的内嵌图标版本变更时通知 Shell 更新文件及图标缓存；不删除缓存文件、不重启 Explorer。窗口显式设置大小图标，避免只依赖类图标。验证实际窗口、任务栏/任务管理器可见状态，区分文件资源正确与 Shell 展示刷新。

核验：Release 构建通过。正在运行的开发目录 exe 与正式发布 exe 均只有新蓝色图标资源；加入通知后，已打开的任务管理器对开发路径仍保留绿点。关闭本程序并从正式发布入口 `artifacts/BlueAudioSink-0.1.0.exe` 启动，实际核验任务管理器条目已显示蓝色音频图标，确认路径缓存参与了问题。当前保留正式发布入口运行。未删除图标缓存文件、未重启 Explorer，未强制结束任务管理器。窗口与 Shell 图标刷新机制已补齐；未取得独立任务栏截图，不将标题栏/任务管理器核验写成任务栏视觉验收。
