# 手机媒体与麦克风双路开发

## 已确认的行为

- 默认：手机媒体声进入电脑耳机，手机麦克风进入 VB-CABLE 虚拟麦克风。
- 电脑端“分享手机声音”默认关闭。开启后，耳机继续播放媒体声，虚拟麦克风接收手机麦克风与手机媒体声的混音。
- 不采集电脑自身的游戏、会议或其他系统声音。
- 使用标准版 VB-CABLE；首次安装引导负责下载、解压、启动官方安装器。用户确认管理员提示，在官方窗口安装，按官方要求重启。随后应用检测设备，会议软件首次选择 CABLE Output。
- 保留 VB-CABLE 来源与 donationware 说明，遵守 https://vb-audio.com/Services/licensing.htm 。

## 当前阶段：协议和分流核心

此阶段尚未接入生产采集与接收路径，不代表端到端麦克风功能已完成。

新增 BAS2 音频包，magic 独立于 BAS1，旧接收端不会把麦克风误当作媒体播放。20 字节头：magic(4)、stream(1)、flags(1)、reserved(2)、session(4)、sequence(4)、timestampUs(4)，均为小端。stream 0 为媒体，1 为麦克风；两路各自维护序号，同一非零会话 ID。PCM 暂沿用 48 kHz、16-bit、双声道、5 ms / 960 字节。Android 与 C# 使用相同 golden header 回归。

PhoneAudioRouter 提供两个独立消费者：耳机只读取媒体；虚拟麦克风读取麦克风和可选媒体。开关清除分享队列，避免重新开启时播放旧内容；不清除耳机队列。混音使用饱和运算，避免整数溢出产生反相峰值。路由器必须由接收与设备管理层协调生命周期：设备缺失时不要无限向无人消费的缓冲写入；停止、断线、切换源时清空全部缓冲。

验证：26 项 C# 回归通过；Android JVM 额外验证编码 golden header 与非法参数，与原有连接测试合计 6 项。JVM 使用临时 Android 平台桩，不替代 APK 或真机验证。

## 待接入

1. 新版能力协商：只有明确支持 BAS2 的双方才启动双路，旧版本保留媒体单路。会话与来源绑定，过期会话不混入当前音频。
2. Android 增加明确的麦克风开关、单声道采集到双声道 PCM 转换、microphone 前台服务权限，与媒体采集并行并正确停止、撤销权限和释放线程。
3. 接收端按两路分别重排、超时、统计；媒体正常缺失不阻塞麦克风，麦克风缺失不阻塞耳机。
4. Windows 显式选择物理输出与 VB-CABLE 播放端，两个设备独立读取；虚拟设备不可用时提示，不回退到耳机播放麦克风。
5. 接入分享按钮、设备状态和驱动安装引导。固定官方来源，验证下载与安装结果，不自动重启。
6. 完整构建和真机验收，包括双路并发、开关连续性、授权撤销、长时间时钟漂移及设备拔出。
