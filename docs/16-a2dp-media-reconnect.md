# Windows 0.3.3 Candidate：手动恢复 A2DP 媒体

日期：2026-10-31。Windows 为 `0.3.3-candidate`；Android 继续使用已发布的 `0.3.2-candidate`，本次不改变手机采集策略或协议。

## 现场证据

用户确认：纯媒体播放、不发送麦克风时同样无声，因此不能归因为麦克风抢占。完整断开再连接后，用户确认媒体声音恢复。

通过 `SinkProbe device <A2DP端点ID>` 直接读取真实设备：恢复前 8 次输入峰值均为 0；恢复后 8 次均有信号（约 0.04–0.36），默认输出也出现约 0.09 的峰值。设备音量未静音，默认输出仍为用户当前的物理输出。

该 A2DP 输入能通过指定 ID 直接读取，且状态为 Active，但通用 Core Audio 端点枚举列表未列出。不能把“枚举遗漏”当作端点不存在，也不能只凭 Active 或默认输出的其他声音判断手机正在发声。已有界面在这种情况下会显示链路已建立、等待声音。

底层为何进入无音频状态仍未确认，可能涉及系统或设备连接状态。此次交付的是明确的恢复入口，不宣称已根治所有断流原因。

## 行为

旧“连接”按钮会复用同一个 AudioPlaybackConnection，重新 OpenAsync；现场连续点击仍无声，完整释放后重建才恢复。

新按钮在未连接时显示“连接媒体”，已连接时显示“重新连接媒体”。手动点击向 SinkController 的串行命令队列提交一个完整恢复操作：保留当前目标 ID，释放媒体连接，再创建、武装并打开新连接。该命令不调用蓝牙麦克风的 Disconnect/Stop；原“断开”按钮仍按原语义同时断开媒体与麦克风。

自动连接、自动重试沿用原复用与退避策略，不添加定时强制重连，避免把正常暂停当作故障。用户正在使用的旧程序不会被自动结束或替换。

## 验证与交付

- Windows Release 自包含 x64 单文件发布通过，GUI 子系统处理通过，保留已有 NAudio/内建 COM 裁剪警告。
- 已有现场断开/连接序列及恢复前后信号验证是本次行为的依据。
- 新按钮通过编译检查；目前控制器直接依赖 WinRT，缺少能无损模拟连接对象生命周期的回归接口，未添加只检查命令字符串的替代测试。新发布按钮及媒体重连时的麦克风并行稳定性仍待实机验收。
- 诊断工具增加 `device <端点ID>` 命令，直接读取设备静音、音量和 8 秒峰值，不修改音频设置。

产物位于 `artifacts/BlueAudioSink-0.3.3-Candidate/`；其中 Windows 为 0.3.3，配套 APK 保持 0.3.2。源码、日志及构建证据与实际验收边界分开记录。
